# Jusage TOKENBOUND — 기존 Agent에게 전달할 첫 실행 프롬프트

기존 Jusage 프로젝트에서 **Humans Inside the Limit** 세계관을 기준으로 새 디자인 개발을 재개한다. 프로젝트를 새로 만들거나 세 기기 간 이사를 다시 하지 않는다.

## 프로젝트 목표

'우리는 AI로 더 많은 것을 할 수 있게 되었다. 그런데 언제부터인가, 남은 토큰을 세며 살아가고 있다.'

Jusage의 트레이는 숫자로 된 세계다. 인간 한 명이 100%의 풍요로운 감금 상태에서 0%의 영원한 쳇바퀴로 떨어지는 과정을 표현한다. 100%는 자유의 착각이며, 초기화는 탈출이 아니라 또 다른 반복이다.

첨부한 `WORLD_BIBLE.md`와 `SCENE_STORY_MAP_0_100.json`을 **서사적 기획의 기준**으로 읽는다. 101개 장면은 구상한 시드이며, 검증된 아트/구현으로 취급하지 않는다. 더 나은 창작 아이디어가 나오면 근거를 들어 개선하되, 0=쳇바퀴·1=숫자 절벽·98=두 방·100=풍요로운 우리라는 앵커는 보존한다.

## 2. 예술 콘셉트: 실제 그림 먼저

1. 기존 98% E안은 재제작하지 말고 시각 기준선으로 삼는다.
2. 100% (`100` 안 화려한 도시/자유의 착각), 50% (문턱/첫 압박), 1% (`1` 절벽에 매달린 인간), 0% (`0` 안의 쳇바퀴)에 대해 원본 16×16 격자 기반 정적안과 확대 콘셉트를 각각 만든다.
3. 97→98→99의 디자인이 같은 세계와 동일한 인간의 시간이라는 것이 연결되는지 확인한다.
4. 숫자 안에 인간을 억지로 겹쳐 숫자를 훼손하거나, 숫자 아래 작은 사람이 별도로 배치되는 과거 실패 방식 반복 금지.
5. 16px에서 세부 행동이 의미를 전달하기 어려우면 실제 비교 시트와 '읽히는 것/안 읽히는 것'을 구분해 보고. 확대 그림을 실트레이 PASS로 주장 금지.

## 3. Playground 구현

1. 승인 가능한 최소 후보만 기존 Rust/Win32 Playground 렌더러에 추가한다. 가능하면 기존 native 렌더링 경로를 재사용.
2. 실제 인증/사용량/설정/기록을 손대지 않고 `--tray-playground --tray-value N`로 0,1,50,97,98,99,100을 확인할 수 있어야 한다.
3. 정지 모드와 Reduced Motion, 아이콘 리소스 수명, 정상 종료를 확인한다.
4. 250ms 프레임과 CPU/GDI 영향은 이전 E안 기준선과 비교한다. 장면별 프레임 수는 가독성에 필요한 최소로.
